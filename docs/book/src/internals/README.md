# 内部手册

面向 wjsm 开发者：解释每一层由谁拥有、数据如何流动、哪些不变量不能破坏。

阅读顺序建议：

1. [目标与架构基础](foundations/index.html)：项目边界、crate 地图、依赖方向。
2. [编译与执行流水线](pipeline/index.html)：从源码到执行的完整链路。
3. 之后按需进入前端、IR、模块、后端、Host/Runtime、GC、启动等分区。
4. 动手改代码前先读 [开发与扩展](development/index.html) 对应主题，再看 [内部参考](reference/index.html) 的 owner 与不变量清单。

用法层面的问题（命令、配置、环境变量、故障排查）在[用户手册](../user/index.html)，本手册不重复。

> <details><summary>「内部手册」和「用户手册」的区别是什么？</summary>
>
> 用户手册回答「怎么用 wjsm」——命令怎么敲、配置怎么写、报错怎么定位。读者是「wjsm 的使用者」，目标是完成具体任务。
>
> 内部手册回答「wjsm 怎么实现的」——crate 怎么划分、数据怎么流、哪些不变量不能破坏。读者是「wjsm 的开发者或深度定制者」，目标是修改或扩展。
>
> 两者在「深入了解」链接上交汇：用户手册的每章末尾会链到内部手册的相关章节，告诉你「如果你想知道为什么是这样，去看这里」。这种单向链接避免了用户手册的章节塞进太多实现细节。
>
> 物理上共用同一份 mdBook——这意味着搜索、目录、交叉引用都在一起。靠导航栏的「用户手册 / 内部手册」两个 Part 来区分。
>
> </details>
